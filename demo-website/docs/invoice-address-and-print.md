Invoices reflow on phones: issuer/recipient and date fields stack, and each service/payment-plan row becomes a labelled card. Screen-only request forms are excluded from print. Print requests A4 portrait with 12mm margins. Long invoices may need multiple pages; native printer settings still control the actual paper selection.

Settings stores personal and company addresses separately. The personal default comes from the student account address, city and country. A complete saved company name and company address take priority on newly issued invoices. Migration 45 preferences remain readable without rewriting existing account data; migration 46 adds independent address columns. Saving an address never edits an issued invoice. Account closure clears both address preferences.

Issued invoice addresses are fixed. Migration 46 adds append-only invoice_address_versions. On the first read, a recorded invoice recipient is captured as version 1. A historical missing address is captured from the account once, when available, rather than dynamically changing on every download. An address change requires a student-owned, CSRF-protected request, with immutable current/wanted name and address and a checkbox acknowledging replacement. A single pending request per invoice is enforced in application code and with a unique generated database key. Drafts, void invoices and credit notes cannot be requested. The saved-address dropdown retrieves only the authenticated student's details; custom company names/addresses have bounded validation.

Admin Payments has an Invoice address requests tab. Only pending student requests expose an approval form. The office sees current versus wanted addresses, can use the submitted address, select either saved account address, or enter a correction, and can approve or decline with a reason. The invoice and request are locked in the same transaction; duplicate reviews and stale base versions are rejected. Approval appends an address correction version, marks the request reviewed, writes an audit entry and queues an email atomically. Original invoice rows, prior address versions, amounts, payments and invoice number remain unchanged. Portal/admin downloads always show the latest approved version, including a version label and bilingual supersession notice. Previously downloaded local PDF files cannot be remotely erased; the warning and email instruct the student to replace those copies.

This implements an address correction linked to the original invoice, rather than a monetary cancellation/rebilling. Official correction reference: https://www.gesetze-im-internet.de/ustdv_1980/__31.html . Approval requires the office to confirm the intended recipient. Structured e-invoice generation is outside this existing HTML/print workflow.

Email confirmations and approved/declined decisions use lib/mail-template.js (LangNation seal, colours, text alternative). Notifications are queued in the same transaction as the request/decision. lib/invoice-address-mail.js attempts delivery immediately and checks persisted queued messages every minute after startup. SMTP failures retry with exponential delay capped at one hour; a ten-minute token lease prevents concurrent workers claiming the same message. Sent messages are filed in the existing Sent folder. As with SMTP generally, delivery is at least once: a process crash after SMTP acceptance but before recording sent_at can result in a duplicate. No external email is sent by automated/local UI tests. SMTP configuration is required for production delivery, and the admin request screen shows sent/queued status.

Migration MySQL/46_invoice_address_requests.sql is additive and discovered by the startup schema migration runner; no existing invoice/payment rows are updated by the migration. The workflow is guarded by column probes until the schema is available. Tests cover ownership, CSRF, company priority, stable repeated downloads, pending-request uniqueness, approvals, declines, stale versions, immutable originals and mail retries. Browser QA uses fake account/ledger data on loopback.
